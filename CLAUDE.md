# duelcommanderpiacenza.github.io

Static site (vanilla HTML/CSS/JS, **no build step**, no framework, no bundler) for the Magic: the Gathering "Duel Commander Piacenza" player group — leagues, events, match results, commander/archetype stats, player standings. Backend is Supabase (Postgres + Auth + Storage). Hosted on GitHub Pages. Italian-language UI, written in Italian; an **English version** is a translation layer on top — see "Language (IT / EN)" below. **It isn't a club: never call it "il club" (or "del club") in any user-facing text** — say "Duel Commander Piacenza", or rephrase ("tra tutti i giocatori", "gli ultimi 10 eventi").

- **The stylesheet is `css/` — six files, `1-base-header-home.css` … `6-dark-tabbar-transitions.css`** (since 2026-10-16: the old single `styles.css`, ~16k lines, split **in its original order**, so the cascade is unchanged): loaded in that order by every public page (the `<link>`s are in `partials/head.html`) and by `admin/index.html` (before `admin/admin.css`). **Keep the order; later rules win ties** — a rule's place in its file, and the file's number, matter. The names say roughly what each mostly holds, but areas are interleaved (that's why it wasn't reorganised by area — moving rules could change which one wins). `url(...)` inside them is relative to `css/` (`../dc_pc.svg`). **Everywhere in this file and in code comments, "styles.css" means these files** (search them for the quoted section names).
- No React/Vue/etc. Pages are plain `.html` files; each loads `js/layout.js` (shared header/nav/search/theme/tooltips) plus one page-specific module — usually `js/*-page.js` or `js/*-detail.js`, but `index.html` uses `js/home.js` and `social.html` `js/moxfield.js` — mounted by `js/router.js` (see "In-app navigation" in docs/modules.md), not by a script tag of its own. **`sw.js` must stay at the site root**: a service worker only controls pages at or below its own folder, so moved into `js/` it would control nothing (GitHub Pages can't send the `Service-Worker-Allowed` header that would lift that), breaking the PWA install.
- **No visible titles on the main pages** (Bacheca, Leghe & Eventi, Giocatori, the Meta pages, Social) — the nav / tab bar names the page; each keeps its `<h1>` for screen readers (`.page-heading.visually-hidden`, or inside the Meta pages' `.meta-head`). The filters' button: **Giocatori** at the end of the "Cerca" line (search, sort, the button), that line and the filters' panel inside `.page-loading-region` (shown with the list once loaded, a search placeholder in the skeleton); **the Meta pages**: in the sub-tabs' row — see docs/ui.md → the Meta section. Opening a filter panel that's scrolled away above (the button on a sticky row) scrolls back to the top (js/filter-toggle.js).
- **The shared page shell lives once, in `partials/`** (since 2026-10-16): `head.html` (the start of `<head>`: charset, the theme / touch inline script before first paint — itself `theme.html`'s markers —, the stylesheets, viewport, icons, manifest, theme-color and apple meta tags), `header.html`, `nav.html`, `footer.html` (with the two closing scripts, supabase-js and `js/layout.js`) — copied into all 15 public pages between `<!-- shell:<name> -->` … `<!-- /shell:<name> -->` markers by **`python scripts/sync-shell.py`** (`--check`: report pages out of sync, exit 1). **Edit the partial, never the copies in the pages, then run the script.** The pages stay plain static files (GitHub Pages serves them as they are; a runtime fetch-include was tried long ago and dropped — the header popped in late and couldn't take part in the page transitions). Per-page parts stay outside the markers: `<title>`, the description, the modulepreload list, `body[data-active-nav]`, `<main>`. A new public page: copy an existing one (markers included) and run the script. The admin (`admin/index.html`) has its own shell except the theme script (`<!-- shell:theme -->`, synced too: the script syncs `partials/` first, then the pages and `admin/`). `.githooks/pre-commit` runs both `sync-shell.py --check` and `sync-preload.py --check` and stops a commit with a page out of sync (since 2026-10-28).
- **Each public page's `<head>` lists every script it will load as `<link rel="modulepreload">`**, between `<!-- preload:modules -->` … `<!-- /preload:modules -->` before `</head>` — written by **`python scripts/sync-preload.py`** (`--check`: report pages out of date, exit 1): the static-import closure of `js/layout.js` plus the page's own module (from js/router.js's `PAGES`; dynamic `import()`s left out). Without a build step the browser otherwise finds them one import level at a time, a round trip each, before any data request can start; with the list it fetches them all at once (first visits / expired cache). **Run it after changing any script's imports** (or adding a page to `PAGES`) — an outdated list isn't an error, just a module loaded the old way or one fetched for nothing. In-app navigation ignores the next page's head (js/router.js takes only `<main>`), so the list only matters for a full load.
- **The logo is `dc_pc.svg`** (two paths, the lotus `#db171c` and the "PIACENZA" lettering `#d10104`; traced from `dc_pc.png`, which stays only as the source): the header's `.site-logo-sm` (white by a CSS filter on the desktop bar, brand red by a CSS mask on touch screens), the player card's foot (`.pc-logo`) and blank art (`.pc-art::before`), the touch search overlay's backdrop, the install prompt, the recap's heading, the admin's header and login. Browser-tab icon: `favicon-96.png` (96px, for browsers wanting a PNG) then `dc_pc.svg` (`type="image/svg+xml"`) in every page's head. The PWA / apple-touch icons are their own PNGs (phones require them).
- **Search engines (Google)** (since 2026-10-26): the site is verified in Google Search Console by **`googled85d93d790569e28.html`** at the root — **never delete or rename it** (the verification lapses). **`sitemap.xml`** (pointed to by `robots.txt`, which keeps `/admin/` out) lists the main pages plus every player, commander, league, closed event (with its date) and the 5 archetypes — rebuilt by **`python scripts/update-sitemap.py`** from the live database with the public key (read from js/supabase-client.js's `LIVE`), run daily by `.github/workflows/update-latest-decks.yml` and committed when it changes; account.html is left out. Every public page has a `<meta name="description">` after its `<title>` (per page, outside the shell markers); the detail pages set `document.title` to "<name> - Duel Commander Piacenza" once loaded (player, commander, league, event, archetype). A new public page: give it a description and, if it should be found, add it to `MAIN_PAGES` in the script. Moving to a custom domain: change `SITE` there and the `Sitemap:` line in robots.txt, and add the domain in Search Console (Change of address).
- **Mockups are named `_mockup-<subject>.html`** (e.g. `_mockup-league-recap.html`), at the site root so `python scripts/serve.py` serves them with the site's CSS: `.gitignore` has `_mockup*`, so they are never committed or pushed (GitHub Pages would publish them). Never name one `mockup-….html` without the underscore.
- Two separate installable PWA identities: the public site (`manifest.json` at root) and the admin app (`admin/manifest.json`), each with their own icon set — admin's icons are the same club logo recolored black instead of red, both use `id`/`scope` to stay distinct as separate installs from the same origin.
- **New accent-colored UI elements (buttons, badges, small floating controls, etc.) should default to the brand-red family** (`--brand-red` and friends, `rgba(220, 24, 28, ...)` for translucent variants) rather than a neutral dark/gray tint — an explicit standing preference, not just this one element's choice. `.badge-status-open` and the commander-detail flip button are the existing examples to match.

## Database, migrations, local dev

No ORM — `js/db.js` is a thin wrapper: `Entity.method()` functions that `await` a Supabase query and throw on error. **PostgREST returns at most 1000 rows per response and silently truncates the rest** — any query that can grow past that (batches across events, whole-history lists) should go through db.js's `selectAllRows` (pages with `.range()`, needs a deterministic order ending on a unique column). `EventEntries.listAll` / `Matches.listAll` (auto-badge rules) are paged this way too. League pages, the Bacheca, badges **and Giocatori/Comandanti/Archetipi/Matchups** load events via `fetchEventsResults(eventIds)` — entries + matches in 2 paged requests per chunk of 100 event ids (the ids go in the URL, so a whole-history scope is chunked to stay under URL length limits), regrouped per event — rather than 2 requests per event; the Bacheca charts use `EventEntries.listForChartsSince` (date-filtered by the DB, only the columns they need). Grouped by table:

RLS: public read is scoped so an open (unpublished) event is only visible while its date is today or in the future (`is_open = false or event_date >= current_date`) — a "save the date" preview that disappears from public view once its day has passed and it's still not closed; entries/matches are gated to closed events only. All writes (and seeing unpublished data) require `is_admin()` — the account listed in the `admins` table, added by migration 001 — not just being signed in, since players can have accounts too; the admin app likewise refuses any account `is_admin()` rejects (`admin/js/auth.js`'s `isAdmin`, checked in `app.js`'s `handleSession`). Changes to an existing database go in `supabase/migrations/` (numbered, each with a rollback) **and** are folded into `schema.sql`, which stays the from-scratch setup. **Migrations 001–027 were applied to both databases and their files deleted on 2026-10-23** (still in git history — see `supabase/migrations/README.md`); a "migration NNN" mentioned here or in code comments means that change, now part of `schema.sql`. The next number is in `supabase/migrations/README.md`. Running locally (localhost/127.0.0.1), `js/supabase-client.js` connects to the separate **dcp-dev** Supabase project instead of live, so local testing never touches real data. **Serve it with `python scripts/serve.py` (port 8000), not `python -m http.server`**: the plain server sends no caching header, so the browser keeps its own copies for a while and, as files are edited, mixes old and new scripts — an old module missing an export the new one imports shows as the page's "errore nel caricamento" (fine after a reload); scripts/serve.py sends `Cache-Control: no-cache`. And js/router.js fetches the next page's HTML with `cache: "no-cache"` (always revalidated: a stored old copy with new scripts crashed the page — also possible on the live site just after a deploy); a page's script should still tolerate an element missing from an old copy of its HTML (event-detail.js / league-detail.js's hero buttons do). **Player login (Google accounts, claiming a player — `player_claims`, the user's own pending request, approved in the admin's "Utenti" tab —, the player card — `profiles`, own row only) is live — plan, decisions and history in `PLAYER_LOGIN.md`.**

**Tables** (details in `docs/data-model.md`): `leagues` (incl. Topdeck series, `is_topdeck`) · `events` (incl. external events) · `event_entries` · `matches` · `commanders` (banned / new badges) · `players` (manual badge slots, linked account) · `badges` + `player_badges_auto` (automatic badges, a derived cache) · `event_standings` and `player_progress` (derived caches) · `decklist_submissions` · `user_settings` (theme, vibration, language) · `user_activity` · `announcements` (the bell; automatic "Risultati online") · `admins`, `player_claims`, `profiles` (login and the player card — see `PLAYER_LOGIN.md`). **Derived caches are rebuilt by `syncAutoBadges`** on event open / close / delete and league changes.

## Rules worth knowing everywhere

- **Every page's `<head>` has an inline synchronous script** (before first paint) that sets `data-theme`, adds `html.nav-mobile` + `html.app-header` on any touch screen (`navigator.maxTouchPoints > 0` — no width check, no media query; touch-only CSS is gated on the class alone, see gotcha #9) and, for English, `<html lang="en">` + `js/i18n-en.js`.
- **Pages load in as few rounds of requests as they can**: start every request that needs only the page's id at once, the dependent ones in a second round; give an early request awaited later a no-op `.catch(() => {})`.
- **Hero pages take the hero's colour as their accent** (`data-accent-from-hero` on `<main>`): a new red element's shadow / tint mixes `var(--brand-red)`, never a literal red, or it stays red there.
- **Entrance animations**: reuse `entrance-fade-up`; one declared with a selector stronger than `body.is-loading *` needs its own pause rule, and every one goes in the reduced-motion list (css/1) — details in `docs/ui.md`. Titles are never animated.
- **A page whose layout changes needs its loading placeholder (`.sk-page`) updated to match** — sizes measured against the loaded page (`docs/ui.md`).
- **General rule, not just a gotcha — worth applying proactively, not only when something visibly breaks**: any popup/dropdown/tooltip (a select's own menu, a date picker, a search dropdown, a table-cell tooltip, a close button meant to float above everything) must reliably paint above ordinary static page content around it — chart cards, data tables, nav bars, whatever else happens to be a sibling or nearby ancestor. This site has hit the *same underlying failure* from several different specific causes now (gotchas #1, #2, #10, #11, #12, #13 below — #4 retired) — an `overflow: hidden` ancestor clipping it outright, a stacking context accidentally trapping its `z-index` below a later sibling, an animated `transform` hijacking a `position: fixed` element's containing block. When adding any new popup-like UI, don't just give it a z-index and assume it works — actively check: (a) does every ancestor between it and the page root allow `overflow: visible` at the moment it's shown (not necessarily always, e.g. during a collapse animation), and (b) does any ancestor's `animation`/`transition`/`transform`/`filter`/`perspective`/`view-transition-name` force an unintended stacking context that caps its `z-index` below whatever it needs to outrank.

## Language (IT / EN)

Since 2026-10-30 (user's choices: public site + privacy only — **the admin stays Italian**; **database content stays as entered** — event / league names, announcements, player and commander names — except the badges (a fixed set, in the dictionary) and the word "Tappa N" → "Leg N" inside any text; default **always Italian** until English is picked; section names translated: Bacheca → Home, Leghe & Eventi → Leagues & Events, Giocatori → Players…).
- **The site stays written in Italian.** English is `js/i18n-en.js`, a classic (non-module) script loaded only in English: every page's inline head script (`partials/theme.html`) reads localStorage `lang` = "en" (not under /admin/), sets `<html lang="en">` and `document.write`s the script, so it runs before the body is parsed. A MutationObserver on the whole document translates text nodes and the `placeholder` / `aria-label` / `title` / `alt` / `data-tooltip` attributes as they're inserted or changed (router swaps, rendered lists, popups). **Exact matches only** (dictionary `D`, keyed by the Italian with spaces collapsed) plus `PATTERNS` (regexps for texts with numbers / names: counts, "N° su M", "Tappa N: …", "X - Duel Commander Piacenza" titles, "label: text" tooltips — a function returning null = no match), so unknown text (names, DB content) is left alone. `data-no-i18n` on an element skips it; a textarea's text is never touched.
- **A new Italian interface text needs its English in `js/i18n-en.js`** (dictionary entry, or a pattern if it has numbers or names in it), or it shows in Italian on the English site. A text that never reaches the page (`confirm()`, …) goes through `translate()` from `js/locale.js`.
- **Dates and numbers**: never hard-code `"it-IT"` — use `locale()` from `js/locale.js` ("en-GB" / "it-IT", from `<html lang>`); js/custom-date.js and js/stories.js build their month / weekday names from it.
- **The choice**: `js/language.js` — `chooseLanguage(lang)` stores it (localStorage `lang` = "en"; Italian = no key), saves it for the account when signed in (`UserSettings.saveLanguage`, `user_settings.language`, migration 033) and **reloads the page** (the translation only goes one way). The account's language is read once per sign-in (`firstReadSinceSignIn("language", …)`, like the theme) and, if it differs, applied with a reload. Picked in account.html's Impostazioni ("Lingua") and, on a computer, the footer's IT / EN pill (`#lang-toggle`, beside the theme button, `.footer-actions`; `.footer-spacer` widened to 128px to keep the centre centred).
- Checking: crawl the pages with localStorage `lang` = "en" (Playwright `add_init_script`) and list the texts still in Italian — popups (the "?" dialogs, badge tooltip cards) need clicking open.

## Version

- `js/version.js` exports `VERSION`, **`MAJOR.BUILD`** (BUILD = the repo's commit count with that commit — +1 on every commit; MAJOR raised by hand for a big release), shown small in the footer on the credits' line (`#site-version`, filled by js/layout.js — the footer partial is untouched by a new version; the admin's footer too, by admin/js/app.js). Bumped automatically by **`.githooks/pre-commit`** on every commit (it rewrites and stages js/version.js, keeping MAJOR) — enabled once per clone with `git config core.hooksPath .githooks`.

# Shared JS conventions

Part of the project notes split out of `CLAUDE.md` (read on demand, not loaded every session). Keep it in step with the code: update it in the same change.

- **`custom-select.js` / `custom-date.js`** — progressive-enhancement skins over native `<select>`/`<input type=date>`. Opt-in `data-searchable` on a `<select>` (the admin entry form's player/commander/partner and the match form's Giocatore 1/2) adds a search field at the top of its menu, filtering options as you type (case/accent-insensitive; the menu becomes a flex column so only the list scrolls; ↓/Enter reach the matches, Enter picks the first match only once something's typed). The native element stays the source of truth (`.value`, `change` events, `<option>` list) and is moved *inside* a new wrapper (`.cs-wrap`/`.cd-wrap`), hidden but functional. **This means a select/date field's actual DOM child, once enhanced, is that wrapper — not the original element directly** — matters for any CSS `:has(> select)`-style selector or JS querying `.field`'s direct children. `custom-date.js`'s trigger shows the native input's own `placeholder` attribute when empty (e.g. `placeholder="Dal"` on a from-date filter), falling back to the generic `"gg/mm/aaaa"` for any date input that never set one — opt-in, doesn't change any other date field's behavior. Likewise opt-in: a `data-open-on-today` attribute (the four "Dal" filter inputs) makes the popup always open on the **current** month instead of the selected value's month; admin form date fields don't set it, so editing an old event still opens on that event's month.
- **`player-badges.js`** — badge icons next to a player's name in a row (Giocatori list, league leaderboard, Bacheca standings preview): manual `badge1`/`badge2` (need `Players.list()`'s badge embed — `EventEntries`' own player embed doesn't carry them) + the top `MAX_AUTO_BADGES_PER_PLAYER` cached auto badges. `fetchPlayerBadgesRenderer()` does both fetches for entry-based rows. **Every badge icon anywhere is drawn by `js/ui.js`'s `badgeDiscHtml(badge, size?)`**: the glyph (an `icon_url` image or an `icon` emoji, centered in a same-size box) inside a white disc with a brand-red ring, `.badge-disc` (white so every icon keeps full contrast; a light-red fill clashed with some), sized in em from the surrounding text (`size` sets it, e.g. the admin list cells). Used by the name rows (player-badges.js), player.html's title, the admin badge and player lists, and, via the opt-in `data-icon-disc` on an `<option>`, the custom dropdown (`custom-select.js`, the admin player form's badge pickers). badges.html's big `.badge-card-icon` is the same look at its own 52px size.
- **`commander-carousel.js`** — player.html's "Album comandanti": a card carousel with two looks switched at 880px (JS `desktopQuery` + the same CSS breakpoint; the first card sits in the slot at scrollLeft 0 in both, so positions/`nearestIndex`/`go` are shared; a ResizeObserver keeps the current card in its slot across the switch). Phones: current card centered, neighbours peeking on both sides turned like a drum, both edges faded. Desktop (native scroll-snap track): current card snapped to the track's left edge — lined up with the page margin — the next ones peeking on the right turned away like the side of a drum (track mask fades from the card's right edge to the track's); a card leaving on the left stays flat and fades out through a per-card mask gradient that follows the track's left edge (`LEAVE_FADE`), so nothing animates past the page edge — `applyDepth` sets each card's transform/opacity/mask from its distance to that slot on every scroll frame, so no CSS transition on those; active card shadow cast down-right and focus outline drawn inside, since the left edge clips; ‹ › arrows hidden on touch like `chart-carousel.js`'s, with a 3-dot window between them — current card red, neighbours grey — in the charts' own pill bar (`.chart-carousel-nav` inside `.cmd-carousel-nav`, the same look as Comandanti's); arrow keys; click a peeking card; mouse drag via `js/drag-scroll.js`'s `enableSnapDrag`, same as the chart carousel, a drag released over a peeking card doesn't also jump to it) with the current commander's stats in a 2×2 grid (Volte giocato, Winrate, Prima partita, Ultima partita — Winrate filled in via the returned `setRecords()` once the matches load, whole history, drops skipped, byes counted as wins; its V-S-P record after the percentage, small and muted — `.cmd-carousel-record`) below the cards at every width (css `.cmd-carousel`; card 260px on desktop, `min(260px, 80vw)` on phones like commander.html's). On player.html from 880px the album sits in the left half of `.history-grid`, beside **"Storico partite"** (right): the player's matches grouped by event, one sub-card each (event + league, deck, final position chip from `event_standings`; rounds as rows, score coloured by outcome) in a `.history-panel` that scrolls inside instead of paginating — its column is `.fills-row` (`contain: size`), so the album column alone sets the row height and the matches stretch to it; on phones stacked, album first; there (`html.app-header` below 880px) the list whole, no scrolling inside, with the back-to-top button (a narrow desktop window: capped at 70vh).

Edit mode stacks art, name, form, foot. The "?" pop-up's previews (`.pc-preview`, css/2) are landscape too, up to 104px wide. The Podio bar covers the name's left 70%. **No description** (player.html's public card — `.player-card.no-description`, set by `renderPublicPlayerCard`; account.html's own card always has its "premi ✎" line): the name (and picture) comes down into the bottom row beside the foot — the links pill, if any, between them — instead of sitting over an empty strip. **Only while the name fits there on one line** (with the picture and four links it could wrap mid-word): `fitCardNameRow` (js/player-card.js, on render and on resize) measures it and, if it wraps, adds `.name-own-row` — the name back on its own row the whole width, the links pill under it beside the foot (the layout with a description), the pill only as wide as its links.
- **`card-cosmetics.js`** — the player card's cosmetics earned by playing, from the linked player's `player_progress` row (`applyCardCosmetics(cardEl, progress)`, called by `player-card.js`'s `renderPublicPlayerCard` (player.html) and `account-page.js`'s `renderCard` (on every redraw: it first removes what it added); null progress = no cosmetics). **Each criterion family dresses its own part of the card, so families stack; within a family only the highest tier shows** (`CARD_COSMETICS`: family → stat + thresholds): **Presenze** (events played 10/25/50/100) the frame round the card — silver → animated foil → gold → mythic orange, drawn **as `.pc-frame`'s padding + background with the surface inside** (`--rim`; a ring overlaid on the dark surface showed a black fringe at the corners), a frame wider than none; **Vittorie** (matches won 25/50/100/150) over the art (`.pc-fx-art`, right after `.pc-art`) — light foil → etched foil → rainbow holo → holo + sparks over the whole card (`.pc-fx-sparks`); the moving rainbows loop seamlessly (an oversized `::before` with a repeating gradient translated by exactly one period — a percentage background-position shift visibly reset); **Podio** (top 8s in events of 20+ players 3/10/20) a bar behind the name in rarity colours — grey → gold → mythic orange (`.pc-fx-ribbon`, the nameplate isolated); **Collezione** (distinct commander pairs 5/10/20) a foil seal in the foot like real rares — silver → gold → rainbow (no glint sweeping over it); **Campione** (real leagues won) one gold star after "Dal …" with the number of leagues won beside it (always, even "★ 1"; the leagues listed on hover). The card has **no favourite-colours border**. - **`pull-refresh.js`** (imported by `layout.js`) — pull to refresh, **only in the installed app** (`display-mode: standalone` / `navigator.standalone`, on `html.nav-mobile`; a browser tab keeps its own): pulled down from the page's very top, a white disc with a red refresh arrow (`.ptr` / `.ptr-disc`, z-index 40; no logo, by choice; on a hero page in the page's accent — `body.has-hero-accent .ptr` sets `--brand-red` to `--hero-accent`, dark mode `--hero-accent-light` — grey before the colour arrives, like everything else) slides down from the top edge (`--ptr-y`, half the finger's travel), its red ring filling and the arrow turning (`--ptr-p`); past 72px armed (a pop + `haptic()`), released then it calls **js/router.js's `refresh()`** — the page swapped in again and re-mounted like an in-app navigation to itself (fresh data, no full reload; a page the router doesn't handle: `location.reload()`) — the disc spinning until `body.is-loading` is off (15s at most). Never started over an open `dialog`, the search, while loading, or inside an element scrolled away from its top; a sideways swipe never becomes a pull; the page itself is held still (`preventDefault`, no iOS bounce) while pulling.
- **`haptics.js`** — `haptic("tick" | "confirm")`: a 10ms vibration (confirm: a short double one) only where `hapticsSupported()` — `html.nav-mobile` + `navigator.vibrate` + an Android platform (iOS has no web vibration; a computer's Chrome has the function but nothing to vibrate) — and the visitor hasn't switched it off (`hapticsEnabled()`, localStorage `haptics` = "off"). **Just on / off, by choice**: a web page can set how long a vibration lasts, not how strong, so an "intensity" setting was dropped. The switch: **`haptics-toggle.js`** (`setupHapticsToggle()`, from layout.js) — a round button with the theme button's look (`.theme-toggle.haptics-toggle`, `.is-off` faded + struck-through phone icon) put in place of the footer's empty `.footer-spacer` (left corner, mirroring the theme button; no page markup changed), only where `hapticsSupported()` — in practice never seen, the footer being hidden on touch screens: the same choice is account.html's "Impostazioni" switch (`chooseHaptics(on)`, shared; `haptics:change` keeps the two in step — see `settings-panel.js` in docs/modules.md); a buzz when turned on; kept in the browser and, signed in, for the account (`user_settings.haptics`, migration 024 — null = never chosen; the account's choice wins on sign-in, like the theme). 024 also made `user_settings.theme` nullable with no default (null = never chosen), so a row made only for the vibration doesn't read as "follow the system". Called on a tab switch (`js/tabs.js`, account.html's own tabs — only when the tab changes), a tap on the tab bar (`js/tab-bar.js`), pull-to-refresh arming and the settings' controls. A new tap worth feeling calls it too.
